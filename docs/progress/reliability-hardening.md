## Evidence and changes so far

- The AR7 held-out split remains consumed. Its historical 2/4 valid, 1/4 executable, 0/4 relevant, and 2/4 provider-connectivity results remain in [the public scorecard](../evidence/ar7-evaluation.md).
- A focused transport test first showed that HTTP 429 stopped generation even when the next response succeeded. The unchanged reproduction test passed after bounded transient retries were added to `services/api/src/llm/client.ts`. HTTP 401 remains terminal.
- A focused service test first showed that a provider outage left no attempt record. The service now persists a `PROVIDER_ERROR` attempt with provider/model, response shape, HTTP status, and request count. It stops as `BLOCKED`, not as a reproduced bug or invalid candidate.
- The reproduction adapter now uses the same diagnostic HTTP path for legacy, OpenAI-compatible, and local Ollama generation. The preflight checks provider readiness, MiniShop reachability, and the installed Playwright browser. For an OpenAI-compatible endpoint, a successful `/models` request proves reachability but does not prove the selected model is available; the returned code says so.
- The new evaluation runner requires an explicit new frozen dataset and output path, refuses the consumed AR7 dataset, writes each case with exclusive file creation, retains API errors and timeouts, and prevents changed-config resume. The scorer distinguishes unreviewed assertion failures from independently reviewed report matches. A separate review scorecard command does not rewrite raw outcomes.
- A new isolated MiniShop evaluation runner can seed each frozen variant, verify its source fingerprint, start the local app, and run generation through the same evidence service. It requires a separate explicit flag before any hosted provider receives report and target metadata. The new dataset has 12 held-out bug cases, 2 controls, and 2 development cases. All 16 passed independent browser reference checks; see [the sanitized reference report](../evidence/prospective-v2-reference.md). This is ground-truth validation, not model performance.
- The dashboard now shows provider request count and a clear timeout explanation. A focused UI test failed before this change and passed afterward.
