Bug-to-Proof · Architecture 03

Trust & evidence boundaries

Untrusted text may propose intent; trusted code controls execution

Untrusted inputs

Never executed directly

Bug report textTreated as data, including steps and free-form context.
Provider responseMay be absent, malformed, ambiguous, or adversarial.
Patch proposalCannot modify source until containment, syntax, diff, and review checks pass.
Raw runtime outputStored locally; secrets and payloads are excluded from public evidence.

Trusted enforcement

Repository-owned deterministic code

Discovery inventoryIssues the only routes and control identities candidates may use.
Schema + policy validatorRejects raw CSS, XPath, JavaScript, unknown targets, and ambiguity.
Compiler + evidence runnerProduces and runs contained Playwright code with typed outcomes.
Verification + proofRecomputes hashes, checks gates, and verifies archive contents.

Fail-closed invariants

✓Only `ASSERTION_FAILED` can support reproduction.
✓Accepted test bytes cannot change between phases.
✓Every locator must exist in discovery context.
✓Every proposed edit must remain inside allowed roots.
✓All required regressions must return exit code zero.
✓Proof payload hashes are verified after extraction.
